**Rule.** When implementing `audit-skill-triggers` deterministically (the prompt gives a rubric but no parser — the model writes one each run), avoid two false-below-target sources:
1. **Parse YAML block-scalar descriptions.** Many SKILL.md use `description: >-` (folded) or `|` (literal) with the text on following indented lines. A naive `^description:\s*(.+)$` regex captures only `>-` → length 2 → the skill scores ~0 falsely. Collect the indented continuation lines (folded `>` joins with spaces; literal `|` with newlines).
2. **Don't require the literal word "directly" for the negation criterion, and make it case-INSENSITIVE.** The rubric criterion is "has a `Do not <default> directly` negation clause"; "directly" is the *template's* example, not a required string. Real strong negations omit it ("Do NOT use the Gemini API path", "Do not write ad-hoc Playwright scripts", "Do NOT just summarize"). Match `re.search(r"\bdo\s*not\b|\bdon'?t\b|\bnot\s+just\b", desc, re.I)` — **must pass `re.I`**: on 2026-07-06 a case-sensitive matcher missed "Do NOT use" (capital D) and dropped the negation point for ~half the COMPETITIVE skills. Keep `ALWAYS invoke`/`Use when` literal (the rubric marks *that* one literal).
3. **Count each user-speech quote-type SEPARATELY; never put `'…'` in one big alternation.** A single-quote branch like `'[^']{2,}'` greedily matches from the apostrophe in a contraction ("user's", "don't") across the *real* double-quoted phrases and swallows them → phrase count collapses to 1 (batch-image-gen showed 1 instead of 6 on 2026-07-06). Run separate `re.findall` per delimiter (`"…"`, `「…」`, `“…”`, `‘…’`) and match ASCII `'…'` only word-boundary-delimited and short: `(?<![A-Za-z0-9])'[^']{2,60}'(?![A-Za-z0-9])`.

**Why:** 2026-06-23 night-consolidation Phase 7. First pass reported 17-18/59 below target (avg ~6.7); the tier-map already flagged "recurring false below-target alerts" and the 06-21/06-22 logs showed the same inflated counts. After fixing both pitfalls the honest count was 10/59 (avg 7.75 ± 2.16) — the genuine outliers are only pinokio + 4 plugin-owned code-review-graph skills; the rest are length>350 artifacts. The inflated counts were measurement error, not skill regressions. **Re-validated 2026-07-06:** a fresh nightly scorer hit the same class again — 24/59 below target (avg 6.36) collapsed to an honest 7/59 (avg 8.12 ± 1.78) once the case-insensitive-negation (#2) and apostrophe-swallow (#3) bugs were fixed; the 7 remaining were 3 genuinely-terse business-ops dev skills (explore-codebase/refactor-safely/review-changes @ score 2) + 4 length>350 artifacts. **Re-validated 2026-07-19:** wrote the naive version first (literal-"directly" negation match + single alternation quote regex) — landed at 25/58 below target (avg 6.59), same inflated shape. Applied all 3 fixes → honest 9/58 (avg 7.72 ± 1.72): refactor-safely/review-changes/review-animations (score 2-3, genuinely terse) + review-design/animation-design (length>350 + thin quote count) + book-prism/market-flow-analysis/partner-mode/site-extract (length>350 artifacts). Third consecutive night the naive-first-pass trap recurred — confirms this is a durable authoring pitfall, not a one-off. **Re-validated 2026-08-04:** first night since the scorer was promoted to a permanent file (2026-07-31) where the naive-first-pass trap did NOT recur — the run came in at 8/54 below target (avg 8.19 ± 1.33) straight away, matching the honest shape rather than the ~25/58 inflated one. All 8 are documented artifact classes: 6 COMPETITIVE skills flagged purely for description length >350, plus review-design/animation-design which additionally trip the `allowed-tools` clause of the frontmatter check — both are pure-markdown reference skills with no scripts, so they legitimately grant no tools. That last one is a rubric-strictness artifact, not a defect; do not "fix" those two by inventing tool grants.

**How to apply:** Triggers whenever running/iterating the skill-triggers (or sibling skill-execution/overlap) audit, or reading its report. If a report shows a skill at "length 2" or a strongly-negated COMPETITIVE skill missing the negation point, suspect these two bugs before treating the finding as real. Cross-check against this file and the tier-map's `notes` before writing below-target items to next-session-alerts.
